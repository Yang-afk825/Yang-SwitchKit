# Yang-SwitchKit · 交换机配置命令一键生成

一个离线的 Windows 桌面工具：选厂商、填参数，一键产出**可以直接粘贴到设备的交换机配置命令**，
同时给出**每条命令的详解**与**四厂商命令对照**。

覆盖 **思科 / 华为 / H3C / 锐捷** 四家，每家 **29 类高频场景**，共 **116 组**命令模板、
**1899 行**命令，配 **170 条**命令概念详解，详解覆盖率 **100%**。

从 3.0 起，除了「怎么写」，把变更前后两头也补齐了：

- **整机开局** —— 已生成的场景按开局依赖顺序重排，只留一次保存
- **配置回滚** —— 反推撤销脚本；粘上变更前配置可精确恢复原值
- **配置体检** —— 粘一段现网配置，出风险清单和健康分
- **配置对比** —— 双机 / 变更前后结构化比对，顺序不同不算差异
- **故障排查** —— 现象到命令的决策树，六类典型故障

3.1 起陆续补上：

- **一键转换** —— 填好的整套参数搬到另一家厂商，端口编号按对方习惯换算，
  换算记录明着列在脚本最前面。以前切厂商，另一家的参数是空的。
- **AI 助手（可选）** —— 一句话把参数填进表单；粘配置时给体检加第三层语义分析。
  **不配置就是纯离线版本**，上面这些一点不受影响，命令也仍然由本地模板生成，
  模型碰不到。
- **从现网导入** —— 粘一段设备上的 `display current-configuration`，自动读出
  VLAN 列表、Trunk 口放通与 PVID、管理地址、静态路由，填进表单。
  不用再去设备上一条条看、再手抄回来。
- **验收清单与变更包** —— 每个场景配完之后敲什么确认、看到什么算对；
  写变更单要的「现状 / 命令 / 回滚 / 验收 / 影响范围」一次导出。
- **复制到对端** —— 两端互联（trunk、聚合、ACL 应用到互联口）时，
  本端配完点一下，填对端口名，直接出对端的命令。只换端口，其余照搬，
  不给「一端改了另一端忘了」留口子。

另有一份**单文件网页版**（`docs/web/Yang-SwitchKit-Web.html`），双击用浏览器打开即可查阅，
不需要安装，Mac 也能用。

## 一、怎么用

1. 双击 `YangSwitchKit.exe`（首次启动约 2-3 秒，单文件程序需要自解压）
2. 在「一键生成配置命令」页右上角选设备厂商
3. 右侧是一页到底的参数区，**每个场景一张卡片**，各带一个绿色的「生成脚本」按钮。
   填好某个场景的参数后点它的「生成脚本」，这段命令就落到左边的脚本区；
   想一次全要，点最上面的「生成全部场景」
4. 左侧脚本区点「复制脚本」直接粘贴到设备，或点「导出」存成 .txt
5. 参数填得多的话，点右上角「保存方案」存成 .json，下次「打开方案」接着改
6. 想搞清楚每条命令在干嘛，切到「设备命令详解」页

界面说明：

- 界面是**左侧脚本区 + 右侧参数区**的布局：参数全在一页上，不用来回切场景
- 顶栏的「深色 / 浅色」按钮可切换主题，默认**浅色**（白底卡片 + 浅灰窗口底）
- 每个厂商的参数**分开保存**，来回切换厂商不会把填好的值冲掉；
  已经生成过的场景，切换厂商后会自动按新厂商重算一遍
- 厂家选择条下面那行灰色小字是该厂商的**接口命名习惯**，填端口前先看一眼，
  别把 H3C 的 `1/0/1` 填给华为（华为从 `0/0/1` 开始）
- 脚本区里 `#` 开头的是注释（思科 / 锐捷是 `!`），设备不执行；
  **想去掉注释直接拿去用**，把左下角的「保留注释」勾去掉即可：
  分节标题、逐段说明、风险提示和 `!` 注释行会一起被清掉，
  只留命令本身，场景之间用空行隔开。这时候点「复制脚本」或「导出」，
  得到的就是一段可以直接整段粘到设备上的命令
- 卡片底部的状态行会告诉你这一段是否已生成、生成了多少行；
  参数有问题会直接红字写在这个位置，同时脚本区尾部也会列出「未生成」的场景
- 红色 `[风险]` 是风险项，青色 `[提示]` 是场景说明，粘贴前建议扫一眼
- 勾了多个场景时脚本会自动合并：重复的 `system-view` 只留第一个，
  `save` 只留最后一次，同一条提示不会出现两遍。所以整段粘到设备上，
  不会出现「保存三遍」这种怪东西
  （思科 / 锐捷的 `configure terminal` 不动，原因见 `scg/compose.py` 的说明）

**方案保存**（右上角「保存方案」/「打开方案」）：

存下来的是一份 `.json`，内容是四个厂商全部场景的参数、已生成的场景、
注释开关和主题。填了参数但还没点「生成脚本」的那些也会一起存下来。

标题栏显示当前方案名，有未保存改动时后面跟一个 `*`，关窗口前会先问一句。
快捷键：`Ctrl+S` 保存、`Ctrl+Shift+S` 另存为、`Ctrl+O` 打开。

**另外两种打开方式**：把 `.json` 方案文件直接拖进窗口，松手就打开；
或者把文件拖到 `YangSwitchKit.exe` 的图标上，Windows 会把路径作为参数传进去，
效果一样。命令行也行：`YangSwitchKit.exe 方案.json`。

> 窗口内拖放走的是 Win32 的 `DragAcceptFiles` + 窗口过程子类化
> （Tkinter 自己不支持拖放，本项目不引第三方库）。如果哪天在某个系统上
> 挂不上，只是拖放进不来，按钮和命令行都不受影响。

存成纯文本是有意的——能进 git、能直接用记事本改、能给同事发一份部署同样的规划。
**方案文件和配置脚本不是一回事**：`.json` 给本工具打开，`.txt` 才是粘到设备上的。

## 二、八个页面分别是什么

| 页面 | 作用 |
|------|------|
| 一键生成配置命令 | 左脚本区 + 右参数区，按场景分块生成；脚本区可切「配置 / 整机开局 / 回滚」 |
| 设备命令详解 | 三种视图：本次生成的命令详解 / 该厂商命令手册 / 四厂商命令对照 |
| AI 助手 | 一句话填参数；从现网配置导入现状（可选，不配置也能用） |
| 配置体检 | 粘一段现网配置，三层检查：安全体检 / 语法校对 / AI 语义补充 |
| 配置对比 | 左右各一份配置，结构化比对差异 |
| 故障排查 | 选现象，给出按顺序该查的步骤 |
| 核验说明 | 这一版做了哪些核对、发现并改掉了哪些错误、哪些还需要你自己确认 |
| 使用说明 | 工具的定位、操作步骤、命令正确性说明与使用边界 |

### AI 助手（可选）

**不配置就是纯离线，29 个场景和其它七个页签一点不受影响。**

配置接口地址和密钥之后，多出两件事：

- **一句话填参数** —— 说「给 VLAN 10 20 30 划 8 个 access 口」，
  它识别出场景、抽出参数，回填到主页面表单并生成命令。
  置信度不够或参数有缺失时不会硬填，先列出来让你确认。
- **配置体检的第三层** —— 在体检页勾选「AI 补充语义层」后，
  除了本地的安全体检和语法校对，再补「配置互相冲突」「缺配套命令」
  「策略顺序错了」这类需要读懂整段配置才能发现的问题。

三条边界写在前面：

- **AI 只填参数，不写命令。** 命令永远由本地模板拼，模型碰不到。
- 接口地址填 OpenAI 兼容的就行：DeepSeek、通义、智谱、本地 ollama 都能用，
  换一家只改地址，不用换版本。
- 密钥保存在 `%APPDATA%\YangSwitchKit\ai.json`，用 Windows DPAPI 加密，
  **不会写进 exe，也不会写进方案文件**。把 exe 发给别人，对方填的是他自己的
  密钥，存在他自己的电脑上；就算把配置文件拷走，换个账户也解不开。
- 发送前默认脱敏，内网地址、密码、MAC、设备名会换成占位符；
  不勾选就一个字节都不出本机。

细节和设计取舍见 [docs/AI-MODE.md](docs/AI-MODE.md)。

### 从现网导入（不需要联网）

「AI 助手」页那个「从现网导入」按钮是纯本地解析，**没配密钥也能用**。

粘一段 `display current-configuration` / `show running-config`，它会读出厂商、
VLAN 列表、Trunk 口的放通 VLAN 与 PVID、管理地址、网关、静态路由，
再按你选的场景把能对上的字段填进表单。

两条原则：

- **读不到就留空。** 表单里的值最后会变成要下发的命令，猜一个值塞进去
  就是现网事故。宁可让你多填一个字段。
- **只覆盖能从现状直接反推的场景**：VLAN 划分、管理面、静态路由、端口隔离。
  BGP、MPLS、堆叠这类，现状里没有能当参数用的字段，会直接告诉你没有可导入的内容。

### 验收清单与变更包

配完不是结束。每个场景都会给一组「敲什么、看什么、看到什么算对」——
VLAN 场景就是 `display vlan` 看 VLAN 在不在、`display port vlan` 看 PVID、
`display interface brief` 看接口 up。这是老网工脑子里那套，写下来给新人用。

主页面脚本区那个「变更包」按钮，一次导出五段：

```
一、变更前状态   ← 用过「从现网导入」才有内容
二、配置命令     ← 纯命令，整段可以直接粘到设备
三、回滚命令     ← 按逆序排列，后配的先撤
四、验收清单     ← 敲什么、看什么、看到什么算对
五、影响范围     ← 这次会动哪些 VLAN、端口、ACL
```

写变更单的时候要的就是这五样。

### 脚本区的三种输出视图

- **配置脚本** —— 填参数生成的那几段，带分节标题和逐段说明
- **整机开局** —— 按开机顺序重排：堆叠 → 管理面 → VLAN 与端口 → 聚合 → 生成树 →
  网关 → 路由 → 安全 → 运维 → 保存。段间重复的 `system-view` 会合并，保存只在最后一次。
  管理面和 VLAN 这两段缺失会直接报风险。
- **回滚脚本** —— 反推撤销命令，按逆序执行。每条标了可靠程度：无标记是写法确定的，
  `[近似]` 是撤销后回默认值，`[人工确认]` 是推不出写法留给你处理。
  注释符跟着厂商走（H3C / 华为 `#`，思科 / 锐捷 `!`），整段粘到设备不会因注释符报错。

  回滚视图右上角有「载入变更前配置」：粘上变更前那个接口的配置，原本只能
  `undo port link-type`（回默认 access）的命令，会改成 `port link-type hybrid`（回你原来的值）。
  基线优先覆盖「覆盖型」命令；增量型（`port trunk permit vlan` 这类）仍走撤销。
  `interface range` 里各端口原配置不同时，会拆成独立接口分别恢复。

「设备命令详解」的三种视图：

- **本次生成的命令详解** —— 把脚本区里已有的命令逐条讲清楚：语法原型、作用、参数含义、
  使用注意、版本差异，并附上「同一件事别家怎么写」。脚本区变了，这里跟着变
- **该厂商命令手册** —— 该厂商适用的全部命令概念，按二层 / 三层 / 安全 / 运维等分组
- **四厂商命令对照** —— 同一件事在四家分别怎么写，适合横向记忆

## 四、端口写法

支持简写，程序会按厂商展开成完整接口名：

| 写法 | 展开结果（H3C 为例） |
|------|---------------------|
| `1/0/1-8` | GigabitEthernet1/0/1 … GigabitEthernet1/0/8 |
| `1/0/1-1/0/8` | 同上 |
| `1/0/1,1/0/3` | 两个端口 |
| `XGE1/0/49` | Ten-GigabitEthernet1/0/49 |
| `Te1/0/49` | 同上（思科 / 锐捷按各自命名输出） |

端口连续时会自动合并成 `interface range` 写法，减少命令行数。

## 五、关于命令准确性

**这一点请务必读完。**

命令以四厂商官方命令手册为准逐条核对过，语法、关键字、参数顺序与命令所处的视图都做了比对，
并重点排查了「同一件事各家写法不同」的跨厂商陷阱。这一版修正的典型错误包括：

- **基础 / 标准 ACL 误带协议关键字**：ACL 2000（H3C / 华为）与 ACL 10（思科 / 锐捷）
  只能匹配源地址，规则里不允许出现 `ip` / `tcp` 协议字段，也不能写目的地址与端口。
  修正前生成的 `rule permit ip source ...` 下发时会直接报语法错误。
- **ACL 编号区间按厂商拆分**：思科 / 锐捷的 100-199 是扩展 ACL，与 H3C / 华为的
  2000-2999 基础 ACL 不在同一体系。修正前输入 100 会被当成标准 ACL，规则里的协议与端口被静默丢弃。
- **华为 VLAN 镜像命令**：修正前为 `mirror to observe-port`（少了 `-ing`，且方向取值超出主流版本支持范围），
  修正后为 `mirroring to observe-port <索引> inbound`。
- **锐捷 SSH 服务端未开启**：RGOS 默认关闭 SSH 服务端，修正前缺少 `enable service ssh-server`，SSH 一定连不上。
- **锐捷关闭 Telnet 的多余命令**：移除无对应含义的 `no service telnet`，只保留官方命令。

**但仍需你在设备上确认这些（工具无法替你保证）：**

- **端口名与槽位号**：生成的端口名必须与设备 `show interface` / `display interface brief` 的实际输出逐字一致
- **标注了「版本」「部分版本」的命令**：这类语法随软件版本变化，下发前用 `?` 补全确认
- **堆叠 / IRF / VSU**：随型号差异最大，本工具给出的是骨架，必须对照本机手册
- **地址与参数**：接口地址、虚拟网关、VLAN 编号由你填入，工具不校验是否与现网冲突
- **明文密码**：结果中的密码为明文，仅用于开局，交付前必须统一更换

建议流程：**先在模拟器或实验设备上跑一遍，确认无误再上生产。**

工具生成的是配置文本，**不会连接设备、不会自动下发**——最终执行由你决定。

### 新增场景的额外提醒

第二批加进来的 12 个场景（端口隔离、端口安全、风暴抑制、环路检测、DHCP Snooping、
ARP 防护、IGMP Snooping、OSPF、端口限速、巡检命令、配置备份、日志与时钟）里，
有几处**各家各版本写法差异较大**的地方，工具已经按最主流的写法生成并在结果里标注，
但下发前请务必用 `?` 补全确认：

- **华为风暴控制**：官方命令是 `storm control ... min-rate X max-rate Y`，
  但部分 VRP V5 版本（如早期 S5700）写作带连字符的 `storm-control`
- **华为环路检测动作**：主流写法是 `loop-detection mode port-shutdown`，
  部分 V200 版本的关键字集合不同
- **思科**：思科**没有**环路检测（发探测帧）这个功能，工具生成的是
  PortFast + BPDU 保护 + errdisable 自动恢复这套替代方案
- **锐捷**：环路检测是全局开关，不能按端口单独开关；
  IP 源防护的命令随 RGOS 版本变化，工具没有生成，只给了提示
- **静态 IP+MAC 绑定**：这条命令四家的写法差异最大，工具**不生成**，
  只在结果里给出各家命令模板作为注释
- **巡检命令**：个别 `show` / `display` 命令随版本不同（聚合口状态、光模块信息等）

## 七、二次开发

**加一个场景：** 在 `scg/registry.py` 里加一条 `Scenario`，再到四个 `vendors/*.py` 的
`_HANDLERS` 里注册对应函数即可。界面表单是从参数定义自动生成的，不用改 UI。

**改命令：** 只动对应厂商文件里的函数，互不影响。

**加命令详解：** 在 `scg/explain.py` 的 `CATALOG` 里加一条 `D(...)`，把各厂商的
正则与语法原型写进 `forms`。工具会在自检时报告未覆盖的命令行。

**验证：** 改完跑这四步，全过才算完：

```
python tools/smoke_test.py     # 116 组能不能都生成出来
python tools/golden_test.py    # 输出有没有被意外改动（会打印 diff）
python tools/project_test.py   # 方案文件存进去再读出来是否一致（不需要图形环境）
python tools/ui_smoke.py       # 界面接线：改参数 → 存方案 → 清空 → 打开
```

后两个跟命令内容无关，只在动过 `scg/project.py` 或 `scg/ui/` 时才必须跑，
但一起跑也就几百毫秒。`ui_smoke.py` 在没装图形环境的机器上会自己跳过。

`golden_test.py` 把每个组合的输出存成快照，逐行比对。它防的是「改一家弄坏另一家」——
命令库五千多行，改 `h3c.py` 一个函数，很可能在别的场景上输出变了却没人发现。
输出确实要变时，确认 diff 符合预期后重建快照，把快照和代码一起提交：

```
python tools/golden_test.py --update
```

它同时还守两件事：README 承诺的**详解覆盖率 100%**（新命令漏写详解会报错），
以及 `EXPECTED_FAIL` 里记录的**非法参数必须继续被拒绝**（例如给 H3C 选 HSRP）。

看某个场景的具体输出：

```
python tools/smoke_test.py --show h3c/stacking
python tools/golden_test.py --show h3c/stacking
```

**重新打包：**

```
python build.py
```

## 十一、它和「直接问 AI」的区别

这个问题一定会有人问，先说清楚。

命令手册是公开的静态知识，AI 也能生成，而且更快。所以这个工具的卖点从来不是
「能生成命令」，而是**它敢为生成的命令负责**：

- **逐条核验过**，四家官方手册对照，核的是语法、关键字、参数顺序和命令所处的视图，
  不是「看起来对」。历史上改掉的 7 个错误里，好几个属于看起来完全正常、
  下发才报错的那种（比如基础 ACL 里带了 `ip` 协议关键字）。
- **专门盯跨厂商陷阱**。同一个动作四家写法不同，这类地方最容易出错，
  也是 AI 最常一本正经胡说的地方——ACL 编号体系、默认 VLAN 的四种叫法、
  时区格式，都踩过并改掉了。
- **改动可追溯、可回归**。232 份快照锁住全部输出，改一条命令会立刻暴露
  影响了哪些场景；详解覆盖率维持在 100%，命令和解释对得上号。
- **离线可用，联网也只发必要的东西**。不配置 AI 就完全不联网，生成的配置
  留在你自己的机器上；配了也只发「抽取参数用的那句话」和「体检时勾选的那段配置」，
  发送前默认脱敏。

3.1 加了 AI 助手，但用法和「打开对话框直接问」有两处根本不同：

1. **它不让模型写命令。** 模型只输出 `{"vlans": "10,20,30"}` 这种字段值，
   命令仍由本地模板拼。所以上面那三条（核验过、盯陷阱、可回归）一条都没失效。
   这就是为什么这个功能做得比「接个大模型」麻烦得多。
2. **它把 AI 当第三层，不当第一作者。** 体检页里本地两层先跑、先出结论，
   在线部分只补它们覆盖不到的部分，而且要带上「已经发现了什么」，
   避免模型把已知问题换个说法再讲一遍。

它也有明确的边界：不连接设备、不下发、不校验你的现网参数。序言里那句
「先在模拟器上跑一遍」不是免责套话，是使用流程的一部分。
